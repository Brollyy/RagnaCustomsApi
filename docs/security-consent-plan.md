# Sensitive API and file consent plan

Status: design proposal for RagnaCustomsApi 0.3.x and RagnaModManager.

## RagnaCustomsApi

1. Declare sensitive access in the distributable mod manifest generated by
   `scripts/package.py`.

   The declaration should identify stable permission IDs rather than relying
   on free-form text. The initial declarations are:

   - `ragnarock.game_instance.get_custom_api_urls`: read the game-provided
     `GetCustomApiURLs()` value. This can expose a server URL and an API key.
   - `network.api.ragnacustoms`: send requests to the documented RagnaCustoms
     API using `X-API-Key`.
   - `filesystem.read.game_config`: only if the implementation retains the
     optional Game.ini fallback; this should be omitted if the key is obtained
     exclusively through `GetCustomApiURLs()`.

   Each entry should include purpose, data exposed, whether it is optional,
   and the runtime capability it unlocks. The manifest must declare the
   narrowest scope: no blanket filesystem or network permission.

2. Add a manager-owned consent record to the mod settings contract. It should
   contain the permission ID, granted/denied state, manifest version (or
   declaration hash), timestamp, and an explicit revocation state. Consent
   must not contain the API key itself.

3. Add a read-only sensitive-settings API to the Lua library. The library
   should load the manager-provided consent state before attempting
   `GetCustomApiURLs()`. Missing, stale, or denied consent must fail closed:
   catalog access continues only with an explicitly configured key, and no
   game API or sensitive file is touched.

4. After consent is granted, read `GetCustomApiURLs()` through the existing
   VaRest/UE4SS-compatible runtime bridge, extract only the RagnaCustoms API
   key according to a strict documented URL format, and reject malformed or
   unrelated endpoints. Never expose the key through `getConfig()`, status,
   events, logs, URLs, or error messages.

5. Keep explicit user configuration as an override. A caller-provided
   `apiKey` is used as-is; automatic discovery is optional and must never
   silently override it. Add capability/status fields that distinguish
   `apiKeySource = "explicit" | "game-config" | "none"` without returning
   the secret.

6. Add tests for: missing consent, denied consent, stale declaration hash,
   granted consent, malformed URL, explicit-key precedence, redaction, and
   ensuring no `GetCustomApiURLs()` call occurs before consent. Add a package
   contract test asserting the sensitive declaration is present and narrowly
   scoped.

## RagnaModManager integration request

RMM should add a versioned sensitive-dependency manifest schema and enforce it
at install time:

- Parse declarations from `.rmod` manifests before extraction or activation.
- Show the permission ID, exact data/resource, purpose, and affected runtime
  capability in the install confirmation UI.
- Persist per-mod consent in the mod settings store; prompt again when a
  declaration is added, broadened, or its declaration hash changes.
- Pass only the consent record to the installed mod; do not pass secrets in
  manifests or package metadata.
- Refuse installation when a required sensitive declaration is malformed,
  unknown under a strict policy, or cannot be recorded. Allow an explicit
  user-controlled warning flow only for a clearly defined compatibility mode.
- On install/update, scan declared mod files and known runtime entry points
  for undeclared sensitive APIs/files. A positive finding should block by
  default or show a high-visibility unsafe-install warning with an audit
  record; it must never silently grant access.
- Revoke or invalidate consent when a mod changes its sensitive declaration,
  package hash, or requested scope.
- Expose an audit view showing declarations, consent state, declaration hash,
  and the reason an install was blocked or warned.

The RMM issue should request the schema, install-time prompt, persisted
consent contract, update/revocation behavior, and declaration-mismatch
enforcement as one feature so mod authors can implement against a stable
contract.
